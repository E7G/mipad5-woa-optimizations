# ACPI time/alarm (HAL event 20) triage, 2026-10-28

This is a separate device-level issue from the GPU/MMU Modern Standby blocker. On the tested nabu Windows boot, System events from `Microsoft-Windows-HAL` ID 20 report that a method on the ACPI Time and Alarm device could not be evaluated, status `0xC0000001`. The event payload contains only that status; it does **not** identify the method. Do not claim that `_GRT`, `_SRT`, a particular RTC register, or PEIC is proven faulty.

The deployed DSDT (SHA-256 `6958CC6F88CF083B4BCD5A4F05CF32538BEA98E84E96BE4861629ED9F92560AE`) declares `PRTC` (`ACPI000E`, Time and Alarm). Its `_DEP` names PMAP; `_GRT`/`_SRT` access an ACPI bridge GenericSerialBus operation region. A live PnP check found `qcABD` (bridge), `qcpmicapps` (PMAP) and Windows `acpitime` all started with problem code 0. The separately present `QCOM057E`/PEIC has problem code 28, but it is **not** listed as a PRTC `_DEP`. The nabu desktop manifest [explicitly comments out](https://github.com/Project-Aloha/windows_xiaomi_platforms/blob/main/definitions/Desktop/ARM64/Internal/nabu.xml) the PEIC driver. Installing it blindly is not a supported inference from HAL 20.

The nabu `PRTC` method layout also matches the [public Qualcomm SDM845 PMIC RTC template](https://github.com/edk2-porting/edk2-msm/blob/e1952621f419f8db60ed28271264e1b5184c571d/Silicon/Qualcomm/sdm845/AcpiTables/pmic_core.asl): a 24-byte serial-bus field, a 16-byte time subfield and the same PMAP dependency. This comparison does not prove the runtime bridge transaction succeeds, but it gives no evidence of a nabu-specific field-width typo to patch.

[Microsoft's ACPI device documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/bringup/acpi-defined-devices) describes the Time and Alarm device's role in preserving time across power transitions. It does not imply this HAL event is the cause of the measured 0% DRIPS; the separate GPU0/MMU0 blockers remain established by SleepStudy.

Next gate: capture a narrowly scoped ACPI method-evaluation result, including the exact method and bridge transaction status, on an ordinary boot/time query. Only then compare with the Android PMIC RTC path and propose a minimal reversible ACPI or bridge-driver change. No ACPI table, driver or clock setting was changed in this triage.
